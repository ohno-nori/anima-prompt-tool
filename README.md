# Anima Prompt Tool

現在のアプリバージョン：**v1.3.1**

使ったタグが蓄積され、自分専用のタグパレットが育つ、Anima系画像生成モデル向けのプロンプトエディターです。日本語UIの静的Webアプリで、アカウント・外部辞書・サーバー同期はありません。

## 主な機能

- 固定順の12カテゴリ、折りたたみ、複数行入力、リアルタイム自動保存
- アンダースコア変換、`score_7` / `score_9_up` の保護、アーティストへの `@` 付与、カテゴリ内重複防止
- 保存済み履歴からのカーソル位置対応補完。IME変換中は補完を停止
- よく使うタグの連続追加・削除、カテゴリ別／横断検索、お気に入り、使用作品数／最近／名前順
- ポジティブ・ネガティブの独立プレビューとコピー
- 作品メモの保存、上書き、複製、削除、お気に入り、投稿URL、自由メモ
- 全カテゴリ／選択カテゴリだけの読み込み
- タイトル・メモ・プロンプト検索、作成日の開始／終了指定、お気に入り絞り込み
- カテゴリごとの新規作成時の初期値、ライト／ダーク／端末連動
- JSONバックアップ・確認付き復元、保存失敗と破損データの保護
- iPhoneを想定したPWA、オフラインキャッシュ、更新通知、セーフエリア対応

初期タグ・品質・ネガティブはすべて空です。外見カテゴリだけが開いた状態から始まります。

作品メモ画面は、件数・検索・開始日／終了日・条件クリア／並び順・作品カードの順で表示します。検索対象の選択と「お気に入りのみ」は並び順の右にある「詳細条件」ボタンから開きます。作品のお気に入り登録・解除は、カードを開いた詳細画面から行えます。「条件クリア」は検索条件と並び順を初期状態に戻し、保存した作品やお気に入り自体は変更しません。

## 作品メモのタイトル・URL・コメントを直接編集

作品メモタブでカードを開き、**「タイトル・URL・コメントを編集」**を押します。編集後に「作品情報を保存」で確定します。プロンプトエディターへ読み込む必要はありません。

この操作はタイトル・投稿URL・自由メモ（コメント）と更新日時だけを更新します。保存済みプロンプト、カテゴリ内容、作成日時、お気に入り、タグ履歴・使用数は保持します。同じ作品をエディターで編集中の場合は作品情報を同期し、編集中のプロンプト本文は維持します。未保存の情報を閉じる際は破棄の確認が出ます。

## メモを複写して新規作成

作品メモの詳細下部にある「複写して新規作成」で、そのメモの全カテゴリ（空欄も含む）・タイトル・URL・コメントを新しい編集中プロンプトへ読み込みます。現在の入力内容を置き換える確認後、プロンプト画面を開きます。保存済み作品やタグ履歴はこの時点では増えず、その後の「保存」で別作品として新規保存します。

## タグの並び替え・URL確認・バックアップ日時

- 自由入力欄の下のタグチップを直接ドラッグして並び替えできます。タッチでは約300msの長押しからスライド、PCではそのままドラッグします。折り返し行への移動と画面端での自動スクロールに対応。タップは従来どおり削除で、ドラッグ後の誤削除は抑止します。矢印操作・並び替えモードの切り替えはありません。
- 並び替えは既存の正規化・重複排除を通したタグをフィールドのテキストへ保存し、出力と作品保存にも反映します。括弧や引用符の未完でタグ内容が変わる操作は拒否し、入力修正を案内します。
- URL登録済みの作品カードには「リンクあり」を表示。詳細条件の「URLなしのみ」で未登録の作品を探せます。「条件クリア」で解除します。
- 設定のJSONバックアップに最終書き出し日時を表示します。日時は書き出し処理を実行した時刻で、ブラウザでのファイル保存完了を検出するものではありません。従来の日時項目がないJSONも復元可能です。
- 日時は任意項目 settings.lastBackupAt に記録し、書き出すJSONにも含めます。復元時はそのバックアップに記録された日時になります。記録のない旧データでは「未実施」と表示します。

## YAMLでタグを一括読み込み

編集画面の **「YAMLから一括読み込み」** から、`.yaml` / `.yml` ファイルを選択するか、テキストを貼り付けます。「読み込み内容を確認」でプレビューし、反映方法を選んで確定してください。

```yaml
quality: "bad id, highres"
count: "1girl, solo"
character: "kitakami (kancolle)"
series: "kantai collection"
artist: ""
appearance: "black hair, blunt bangs, braid, long hair"
outfit: "green sailor collar, green skirt, serafuku"
pose: "holding, standing"
composition: "full body"
background: "grey background, simple background"
other: ""
negative: ""
```

- **現在の内容に追加**：既存タグの後ろに追加し、同じカテゴリの重複タグを除きます。空文字は変更しません。
- **YAMLにあるカテゴリを置き換え**：記載カテゴリを置き換えます。`artist: ""` などの空文字はそのカテゴリを空にします。記載していないカテゴリは保持します。
- 内部IDは上記12種類。カンマ区切り文字列のほか、`appearance: [blue_eyes, long_hair]` のような文字列リスト、改行・コメント・コードブロックごとの貼り付けにも対応します。
- アンダースコア・アーティストの`@`等は通常入力と同じルールで変換します。確認するだけでは編集内容を変更しません。
- 読み込み先は編集中プロンプトです。作品メモの保存やタグ履歴への登録は行いません。
- 不明なカテゴリID、重複キー、不正な値、複数文書、エイリアス参照は拒否します。空欄は`""`で指定してください。上限は1MB、各カテゴリは読み込み後20万文字です。
- ファイルは端末内で処理し、外部送信しません。既存のJSONバックアップ機能とは別の機能です。

## 開発環境で起動

Node.js **24 LTS** を推奨します（最低22.12）。プロジェクトフォルダーで実行してください。

```sh
npm ci
npm run dev
```

表示されたローカルURLの `/anima-prompt-tool/` を開きます。通常は `http://127.0.0.1:5173/anima-prompt-tool/` です。`npm install` でも導入できますが、納品時と同じ依存関係には `npm ci` を使用してください。

開発サーバーではService Workerを登録しません。PWAの確認は本番ビルドを使います。

## テストと本番ビルド

```sh
npm test
npm run build
npm run preview
```

`dist/` が配信用の完成ファイルです。プレビューURLは通常 `http://127.0.0.1:4173/anima-prompt-tool/` です。`index.html` を直接ダブルクリックする `file://` 配信では動作しません。

自動ブラウザテスト：

```sh
npm run test:e2e
```

Windowsではインストール済みMicrosoft Edgeを使用します。他のOSでは先に `npx playwright install chromium` を実行してください。テスト用プレビューサーバーは自動起動・終了します。デスクトップと390pxのスマホ相当表示で、実際の本番ビルドを検証します。iPhone相当のエミュレーションはChromiumであり、実機Safariの代替ではありません。

`npm run icons` で同梱PNGアイコンを再生成できます。アイコンは外部画像や画像生成サービスに依存しない専用ベクターマークです。

## GitHubへアップロードする最短手順

以下はGitHubへソースを登録し、GitHub Pagesで公開する手順です。すでにソースを登録済みの場合は、Pagesの設定から進めてください。

**推奨：ソースコード＋同梱GitHub Actionsワークフローを使います。`dist/` のアップロードは不要です。**

1. 自分のGitHubに空の公開リポジトリ **`anima-prompt-tool`** を作成します。
2. 本フォルダーのソースをリポジトリのルートへ登録します。`src/`、`public/`、`scripts/`、`e2e/`、`package.json`、**`package-lock.json`**、各設定ファイル、README、**`.github/workflows/deploy.yml`** を含めてください。`node_modules/`、`dist/`、テスト結果、ZIPは登録しません。
3. GitHubの **Settings → Pages → Build and deployment → Source → GitHub Actions** を選びます。
4. `main` ブランチへのアップロードでワークフローが実行されます。設定前の実行が失敗した場合は、**Actions → Deploy to GitHub Pages → Run workflow → main** から再実行してください。
5. Actionsの `build` と `deploy` が成功したら、Pages設定またはデプロイ結果のリンクを開きます。

予定URL：**https://ohno-nori.github.io/anima-prompt-tool/**

GitHub Desktopを使うと、ドットで始まる `.github/` も含めて登録しやすくなります。Webのファイルアップロードを使う場合、隠しフォルダー `.github/` の入れ忘れに注意してください。フォルダーをもう一段ネストさせず、`package.json` がリポジトリ直下にある構成にします。

別名のリポジトリを使う場合は `vite.config.ts` の `base`、Manifestの `id` / `start_url` / `scope`、`workbox.navigateFallback`、E2E設定とパスの検証を変更して再ビルドしてください。

### ビルド成果物を直接公開する場合

Actionsを使わない場合だけ、`dist/` **の中身**を専用の配信ブランチ（例：`gh-pages`）のルートにアップロードし、Settings → Pagesで **Deploy from a branch → gh-pages → /(root)** を選んでください。`dist` フォルダー自体を配信ルートに入れると予定URLから一段深くなります。ソースの `index.html` はそのまま配信できません。

## iPhoneのホーム画面に追加

1. 公開後のHTTPS URLを **Safari** で開きます。
2. オンラインのまま初回ファイルの取得を待ちます。
3. Safariの共有メニューから **ホーム画面に追加** を選びます。
4. 名前を確認して追加し、ホーム画面のアイコンから起動します。
5. 初回はホーム画面アプリもオンラインで起動してください。以後はキャッシュ済みのアプリでオフライン編集できます。

Manifestは `standalone`、スコープは `/anima-prompt-tool/` です。192px・512px・maskable PNGと180px Apple Touch Iconを同梱しています。画面上部・下部のセーフエリアに対応し、入力欄はスマホで16px以上です。ソフトウェアキーボードが画面を狭めたときは固定操作バーを隠して入力を保護します。

## オフライン利用と更新

初回オンラインアクセス時にService Workerがアプリ本体をキャッシュします。以後、編集・履歴・メモ・検索・コピーをネットワークなしで使えます。投稿先のWebサイトを開く操作には通信が必要です。

新バージョンの検出時は画面に通知します。**「入力を保存して更新」**を押すとドラフトを保存してから更新します。容量不足などで保存に失敗した場合は更新を止めます。自動で編集中の画面をリロードしません。更新後は旧バージョンのキャッシュを整理します。ブラウザを再度開いたとき・フォーカスしたとき・長時間起動時にも更新を確認します。

新しい版が出ないときはオンライン接続で再度開き、必要に応じて通常の再読み込みを行ってください。データを消す前には必ずバックアップを保存してください。

## JSONバックアップと復元

設定（歯車）→ **JSONを書き出す** で、以下を1ファイルに保存します。

- 全作品メモと保存時点の最終プロンプト
- タグ履歴・使用作品との関連・お気に入り
- 編集途中のプロンプトと作品情報
- カテゴリ初期値・開閉状態・追加先・テーマ

iPhoneではダウンロードされたJSONを「ファイル」アプリに保存してください。別端末へJSONを渡し、設定→ **JSONを読み込む** →件数を確認→ **すべて置き換えて復元** で移行できます。

復元はマージではなく全置換です。既存のデータを残すには先に書き出してください。スキーマバージョンは `1`。不正JSON、未対応バージョン、不正な投稿URL、ID重複、履歴の参照破損などは拒否します。インポート上限は20MBです。

保存領域が破損している場合は、自動保存を停止して元データを保持します。設定の「保存領域の元データを退避」で救出し、正しいバックアップを復元してください。別のタブで変更された場合も競合防止のため保存を停止します。現在の内容をJSONで退避してから再読み込みしてください。

## 保存とデータ整合性の仕様

- 保存キーは **`anima-prompt-tool:v1`** のみ。Illustrious版のデータには触れません。
- 自由入力・コピー・自動保存ではタグ履歴を増やしません。作品メモを保存したときだけ登録します。
- 使用作品数は履歴の `workIds` の件数です。同じ作品の上書きは重複計上せず、作品からタグを外したり作品を削除した場合は減ります。使用数が0の履歴も再利用用に残ります。
- 履歴を削除しても作品メモは残ります。既存の全作品を再集計することはありません。削除済みタグを含む旧メモをそのまま上書きしても復活しません。新作品（複製を含む）の保存、または旧作品に新たに追加して保存した場合は再登録されます。
- タグはカテゴリ単位で大文字小文字を区別せず重複防止します。出力は最初の表記・入力順を保ちます。
- 入力中の文字列は変換しません。出力・タグ操作・作品保存で変換します。メモのカテゴリ内容は保存時に正規化されます。
- 括弧内・二重引用符内・エスケープしたカンマは区切らず、重みや交互構文を保持します。自然文もトップレベルのカンマ・改行で区切られます。
- 変換例外は `src/domain.ts` の `UNDERSCORE_EXCEPTIONS` に追加できます。
- 最終プロンプトは保存時点の独立したスナップショットです。設定変更や読み込みで過去の出力を再生成しません。上書き保存を明示的に行った場合にのみ更新します。
- カテゴリ別読み込みは対象だけを置き換え、タイトル・投稿URL・メモは維持します。その後の上書き先は現在編集中の作品です。
- 日付検索は端末のローカル日付における**作成日**を使用し、指定日の両端を含みます。開始日だけ、終了日だけでも検索できます。
- 外部リンクはHTTP/HTTPSのみ。別タブで開き、`noopener noreferrer` を付けています。

## ブラウザ内保存の注意点

作品・タグは**端末とブラウザのlocalStorageだけ**に保存します。GitHub Pagesへ公開しても、ユーザーデータがGitHubにアップロード・同期されることはありません。

ブラウザデータ削除、プライベートモード終了、ストレージの自動解放、端末故障などでデータを失う可能性があります。localStorageの容量は環境依存で、通常は数MB程度です。保存に失敗したら画面の通知を確認し、すぐにJSONを退避してください。保存に失敗した変更は画面内には残りますが、再読み込みで失われます。

Safariの通常タブとホーム画面PWAで、データが常に共有されるとは仮定していません。普段使う起動方法を決め、移行にはJSONを使用してください。複数タブでの同時編集は避けてください。画像ファイルは保存しません。

## ファイル構成

```text
src/
  domain.ts           データモデル、正規化、履歴、メモ、検索、入力検証
  storage.ts          保存、JSON、ダウンロード、コピー
  App.tsx             日本語UIと画面操作
  MemoCollection.tsx  作品メモ一覧と検索操作
  MemoDetailsEditor.tsx  作品情報の直接編集
  YamlImportPanel.tsx  YAMLのファイル・貼り付け・確認UI
  yamlImport.ts       YAMLの検証とカテゴリへの反映
  styles.css          レスポンシブ／ライト・ダーク
  domain.test.ts      ビジネスロジックのテスト
e2e/app.spec.ts        本番ビルドのブラウザ検証
public/               同梱アプリアイコン
scripts/icons.mjs     PNG再生成
.github/workflows/    GitHub Pagesへのビルド・配信設定
dist/                 本番ビルド済みファイル（Git登録不要）
```
